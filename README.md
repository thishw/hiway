# hiway

Product site for [hiway-kit](https://github.com/This-HW/hiway-kit) — served at **https://hiway.thishw.com** (GitHub Pages, Hugo).

- **Content & theme**: contributed by the hiway-kit maintainers via pull requests.
- **Facts** (counts, versions, CHANGELOG, privacy policy) are generated at build time from tagged hiway-kit releases — never hand-written.
- **Operations** (review, merge, deploy, domain): syndicator planning/control session.

Policies: no trackers, no external font CDNs, no ads. AI crawlers allowed.

## Layout

| Path | What |
| --- | --- |
| `hugo.toml` | Site config. `baseURL` is fixed to `https://hiway.thishw.com/`; English at `/`, Korean at `/ko/` |
| `content/` | Home (`_index.*.md` front matter holds the landing copy), `docs/`, `blog/`, `privacy.*.md`, `changelog.*.md` — each in `.en.md` and `.ko.md` |
| `layouts/`, `assets/`, `i18n/` | The theme, written for this site (no Hugo modules or external themes) |
| `static/` | `robots.txt`, favicon, self-hosted fonts with their OFL licence files |
| `scripts/fetch-kit-facts.py` | Writes `data/kit.json` from the latest hiway-kit release tag |
| `scripts/check_site.py` | `hand-numbers`, `origins` and `overflow` checks used by CI |
| `.htmltest.yml` | Internal link check over `public/` |
| `.github/workflows/` | `pages.yml` deploys; `check.yml` is the pull-request gate |

`llms.txt` is generated by Hugo (`layouts/home.llms.txt`) so its numbers come from the same data file.

## Facts: `data/kit.json`

`scripts/fetch-kit-facts.py` finds the newest `vX.Y.Z` tag of `This-HW/hiway-kit` through the GitHub API, downloads that tag's tarball, and writes:

- `version` from `plugins/common/.claude-plugin/plugin.json` (must equal the tag),
- `counts` with the same definitions as hiway-kit `scripts/check_doc_counts.py::count_actuals` —
  agents = `plugins/*/agents/**/*.md` with a `name:` line, skills = `plugins/common/skills/**/SKILL.md`, rules = `plugins/common/rules/*.md`,
- the newest `CHANGELOG.md` entries and the text of `PRIVACY.md`.

Any failure — network, no tag, schema violation — exits non-zero and the build stops; the site never ships last week's numbers silently. The file is not committed, and the theme refuses to build without it.

Content and layouts never contain a count or the current version. Use the data instead:

```text
{{< kit "agents" >}}   {{< kit "skills" >}}   {{< kit "rules" >}}   {{< kit "version" >}}   {{< kit "tag" >}}
```

Blog posts are dated case studies and may name the release in which something changed; that is the only place a version number may be written.

## Local development

Requires Hugo extended 0.163.3 and Python 3.9+.

```bash
python3 scripts/fetch-kit-facts.py                        # latest release tag (network)
python3 scripts/fetch-kit-facts.py --from-path ../hiway-kit  # or a local checkout, offline
hugo server
```

`--from-path` is for local work only; CI always reads the release tag.

## Checks

`check.yml` runs these on every pull request. Run the same commands locally before opening one:

```bash
python3 -m pytest                                  # or: python3 -m unittest discover -s tests
hugo --gc --minify --panicOnWarning                # 1. build, warnings are errors
htmltest                                           # 2. no broken internal links (v0.17.0)
python3 scripts/check_site.py hand-numbers         # 3. no hand-written counts or versions
python3 scripts/check_site.py origins              # 4. nothing loaded from another origin, no trackers or ads
CHROME=/path/to/chrome python3 scripts/check_site.py overflow   # 5. no page scrolls sideways at 390px
```

`overflow` opens every built page in headless Chrome (`$CHROME`, else `google-chrome`/`chromium` on `PATH`; CI uses the one preinstalled on `ubuntu-latest`). Exit 2 means no browser was found.

In CI, Hugo and htmltest are downloaded at a pinned version and verified against a SHA-256 before use.

## Deploy

`pages.yml` runs on push to `main`, weekly on Monday (to pick up new hiway-kit releases), and on manual dispatch: fetch facts → `hugo` → the same hand-numbers, link and origin gates as `check.yml` → GitHub Pages. The gates run on deploy too because CHANGELOG and PRIVACY text arrive from the kit's release tag without a pull request here. Never add `--baseURL` to the build; preview a production build locally with `hugo --baseURL http://localhost:1313/` instead.

## Old addresses

The four posts that moved from `this-hw.github.io/hiway-kit/posts/<date>-<slug>/` declare Hugo `aliases` for `/posts/<date>-<slug>/` on their English page with `alias_to_lang: ko`; those addresses redirect to the Korean version at `/ko/blog/<slug>/` (`layouts/alias.html`). Without `alias_to_lang` an alias redirects to its own page.
